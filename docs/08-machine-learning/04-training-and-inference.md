# Model Training Pipeline & Deployment Gate

## 1. The 40-Session Sliding Window & Cold-Start Strategy

A major challenge in personalized desktop machine learning is the **Cold-Start Problem**: When a user first installs Focus Engine, their local SQLite database has zero recorded sessions.

Focus Engine solves this with a dynamic **Sliding Window Synthesis Architecture** (`dataset_builder.py`):
- The training window maintains a fixed size of **$N = 40$ sessions**.
- **Cold-Start ($t = 0$)**: The window is populated with 40 realistic synthetic sessions generated by `synthetic_generator.py` based on human productivity research distributions.
- **Progressive Personalization ($t > 0$)**: As the user completes real sessions, `real_data_extractor.py` extracts them from SQLite and prepends them to `dataset.csv`, evicting synthetic sessions one-by-one:
  $$\text{RealRatio} = \frac{N_{\text{real}}}{40} \times 100\%$$
- Once the user completes 40 focus sessions, the dataset becomes **100% personalized** to their individual biological and cognitive habits.

## 2. 5-Fold Cross-Validation & The Deployment Gate

Located in `python/ml/train_focus_model.py`.

### 1. Why 5-Fold Cross-Validation is Mandatory
With a small dataset of $N = 40$ sessions, a single standard 80/20 train/test split creates extreme variance:
- Depending on which 8 sessions land in the test set, $R^2$ scores can swing from $+0.65$ to $-0.40$.
- To obtain an objective, statistically valid metric, 5-Fold Cross-Validation partitions the 32 training rows into 5 folds, iteratively training on 4 folds and validating on the 5th:
  $$\text{CV}_{R^2} = \frac{1}{5} \sum_{k=1}^5 R^2_k$$

### 2. The Deployment Gate Algorithm
Before overwriting the production `focus_model.pkl` artifact on disk, the training script enforces a strict performance threshold:

```python
# 1. Load existing model metadata
metadata_path = os.path.join(models_dir, "focus_model_metadata.json")
old_cv_r2_mean = -999.0
if os.path.exists(metadata_path):
    with open(metadata_path, 'r') as f:
        old_cv_r2_mean = json.load(f).get("cv_r2_mean", -999.0)

# 2. Check deployment gate
new_cv_r2_mean = float(np.mean(cv_r2))
should_deploy = new_cv_r2_mean >= old_cv_r2_mean

# 3. Only serialize if equal or improved
if should_deploy:
    joblib.dump(model, model_path)
    # Save updated metadata...
else:
    print("[REJECTED] New model CV R² did not beat old model. Retaining existing model.")
```
This guarantees that an aberrant or noisy training batch cannot degrade the production prediction model.

## 3. Fast CLI Inference Engine (`predict.py`)

Inference executes via a standalone Python CLI script called by Node.js.

### 1. Execution Flow
1. Reads one JSON line from standard input (`sys.stdin.readline()`).
2. Loads cached `.pkl` models via `joblib.load()`.
3. Constructs an ordered NumPy feature array matching `constants.FEATURES`.
4. Dispatches predictions:
   - `focus_model.predict(X)[0]`: Continuous regression score, clamped to $[0.0, 100.0]$.
   - `anomaly_model.predict(X)[0]`: Binary classification ($1 = \text{normal}, -1 = \text{anomaly}$).
5. Outputs JSON response to `sys.stdout` and exits immediately.
